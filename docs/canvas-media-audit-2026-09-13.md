# 画布参考素材检查

## 模型能力提示与图片预览

- 视频创作的“分析与脚本模型”和内容创作的文本模型选择器，按节点自身及连线上游实际引用的图片、视频、音频，标注“未声明…理解”。继承模型的文本节点也显示提示。删除引用、断开连线后提示随之更新。
- 能力判断读取 `runtime_rule.capabilities`，不根据模型名称推测。沿用视频能力的显式布尔值优先规则；图像兼容 `vision` / `multimodal` 声明，音频声明单独判断。
- 输入节点、素材节点、Seedance 参考图和普通生成节点的参考图均接入现有图片预览弹窗。普通生成节点此前只有参考图数量，现在同时显示可点击缩略图。预览保留原始 URL，支持现有弹窗关闭及下载操作。

## 视频创作入口的参考音频接入

初次检查发现音频只被保存，未进入视频创作链路；现已按后续要求接通音频理解及其下游用途。上传或素材库引入的音频将以真实媒体内容发送到分析模型，内容、情绪和节奏用于脚本、分镜及场景创作。

| 环节 | 代码行为 | 是否使用入口参考音频 |
| --- | --- | --- |
| 上传与保存 | `uploadReference` / 素材选择将 URL 和资产 ID 写入 `referenceAudioUrls` / `referenceAudioIds` | 保存并可播放 |
| 脚本与分镜分析 | `run` 通过 `canvasChatMediaParams` 将去重的 `reference_audios` 发送至 `/api/chat/completions` | 模型收到音频媒体内容；提示词要求提取语音、情绪、节奏和带时间段的观察依据 |
| 关键帧与视频场景生成 | 按当前镜头传递分镜的 `audio_reference`、场景、动作和生成提示词 | 使用音频分析形成的场景约束，不将整段音轨重复塞入每个片段 |
| 配音生成 | 台词规划模型读取参考音频，按可辨识内容和用户要求生成结构化台词；配音模型使用台词和选定音色 | 使用分析后的台词与语气，不自动克隆声音 |
| 成片合成 | 保持已有视频与生成配音合成逻辑 | 原音频不自动混入成片 |

音频参与分析的旧历史任务会因执行签名版本变化而重新计算，避免沿用此前未听取音频的结果。音频读取失败、返回 `error`、不支持的媒体能力或协议都会明确失败，不标记为成功。

## 部署与模型配置

- 需要发布 Web、Admin 和 API。没有数据库迁移，也没有自动启用未经验证的模型能力。
- 在模型管理页为实际支持的聊天模型启用“音频理解”，对应 `runtime_rule.capabilities.audio_analysis=true`。线路级显式配置优先于模型配置。
- OpenAI 兼容聊天线路将音频编码为 `input_audio`，支持 MP3/WAV；Gemini 原生线路编码为 `inlineData`。Claude/Anthropic 和当前 Responses 适配路径拒绝音频，不会退化为只发送文字。
- 已有存储 URL 先通过资产所有权校验；外部音频 URL 使用现有防内网请求客户端读取，限制读取时间与文件大小；读取内容按字节识别格式。当前附件解码后总大小上限为20MB，供应商仍可能有更严格的请求大小限制。
- 格式参考：[OpenAI 音频文档](https://developers.openai.com/api/docs/guides/audio)、[Gemini 音频理解](https://ai.google.dev/gemini-api/docs/audio)。

## 验证范围

- 前端回归覆盖上传及连线音频进入请求、音频失败不标记成功、当前镜头收到音频观察依据、旧缓存失效，以及前次模型提示和图片预览。
- 后端测试通过本地模拟 HTTP 模型接口，验证 OpenAI/Gemini 请求确实携带原始音频字节；覆盖格式、大小限制和模型线路能力检查。
- 未调用付费模型或进行真实供应商音频理解质量验收；实际内容识别效果取决于所选模型。
